# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Antopia is a portrait-orientation mobile idle/incremental ant-colony game (Unity `6000.0.43f1`, URP, Android target, package `com.antopia.game`). All in-game text and code comments are in Spanish; keep that convention.

## Build & run

There is no test suite. The project is driven by Unity Editor menu/CLI hooks in `Assets/Editor/AntopiaBuild.cs`:

- **Regenerate materials + `Main` scene + player settings:** menu `Antopia/Setup Project` (`AntopiaBuild.Setup`). The scene is generated by code (a single `Antopia` GameObject with `GameController`), so edit `CreateScene()` rather than hand-editing `Assets/Scenes/Main.unity`.
- **Headless Android APK build** (dev build, IL2CPP, ARM64, min SDK 26, output `Builds/Antopia.apk`):
  ```
  "C:/Program Files/Unity/Hub/Editor/6000.0.43f1/Editor/Unity.exe" -batchmode -nographics -projectPath . -buildTarget Android -executeMethod Antopia.EditorTools.AntopiaBuild.BuildAndroid -logFile build.log
  ```
  Do not pass `-quit`; `BuildAndroid` calls `EditorApplication.Exit` itself with the build result. The committed `apk/Antopia.apk` is a manually copied build artifact; `Builds/`, `build.log`, `Library/`, `Logs/` are untracked/ignored.
- **`build-apk.ps1` / `build-apk.bat`** wrap the command above (`-Copy` also copies the APK to `apk/`); close the editor first, only one Unity instance can open the project.
- **Screenshots without opening the editor:** `capture-shots.ps1` builds a Windows player (`AntopiaBuild.BuildWindowsShots`), runs it with `-antopia-shots <dir>` and saves a PNG of every screen to `Shots/` (see `ShotRunner`, which reloads the scene per step with demo save data). Use it to review any UI or world change visually before finishing.
- `Assets/Editor/ProjectBootstrap/PackageInstaller.cs` is bootstrap scaffolding for headless package installs (its package lists are empty).

## Architecture

The whole game is code-built: no prefabs, no authored UI, no authored 3D assets. `GameController` is the only component in the scene and everything else is created at runtime under `Assets/Scripts/Game/` (namespace `Antopia`).

- **`Game` (static class, `Game.cs`)** – single source of truth: `SaveData` (serialized to JSON in `PlayerPrefs` under key `antopia_save_v1`), economy formulas, offline income (capped at 2 h), and daily-task tracking/reset (keyed by local date). All state mutations go through its methods, which call `Notify()` → `Save()` + `Game.Changed` event. UI subscribes to `Game.Changed` (see `GameController.RefreshHud`) instead of polling. If you add a field to `SaveData`, null/length-guard it in `Game.Load()` for saves from older versions.
- **`GameController`** – entry point (`Awake` loads save, creates canvas, HUD, and adds `NestView`). Owns the HUD, toast, and a single "overlay" panel (Nido upgrades, Diarias); the overlay is rebuilt wholesale on every `Game.Changed`, so overlay builders must be idempotent functions of `Game` state. Handles pause/resume/quit save and offline income.
- **`UiKit`** – helpers to build uGUI in code using normalized anchor rects (`xMin,yMin,xMax,yMax` as 0–1 fractions) inside a safe-area `RectTransform`; uses the Input System UI module and the built-in `LegacyRuntime.ttf` font. Buttons and panels are skinned with the glossy UI pack in `Assets/Resources/UI` (9-slice sprites): `MakeButton` maps its `Color` argument to the nearest skin (`SkinFor`; `UiKit.Disabled` = slate-grey cyan) and takes an optional icon sprite name, `Frame` draws a panel, `SetButtonColor` re-skins a button. `Assets/Editor/UiSpriteImporter.cs` auto-configures anything dropped in `Resources/UI` (sprite + 9-slice borders by `Button*`/`Msg*` prefix) and `Resources/Textures` (repeat wrap).
- **`NestView`** – 3D low-poly scene from Unity primitives (ground, mound, one building per upgrade type, passive ants walking to/from the nest). Materials are loaded by name from `Assets/Resources/Materials/` (created by `AntopiaBuild.CreateMaterials`; buildings use `Despensa`, `Tuneles`, `Camara` and `Twig`).
- **`WorldGame` (the shared world)** – what "JUGAR" opens for every role (`GameController.PlayRole` saves the role and calls `OpenWorld`). The player walks freely with the joystick (no timer) in a world bigger than the nest: `WorldLayout` defines three zones (nest, north, east) separated by stone walls (`AntRunner.Walls`, AABB rects) and two points of interest. The loop is cooperative: the **explorer** (reveal radius 8 vs 3.5) clears `FogGrid` clouds (saved in `SaveData.revealed`), discovers POIs (`poiFound`, +30 coins) and finds gems; the **soldier** walks into the beetle plugging the north gap (an `AntRunner.Blockers` circle) and plays a one-wave `SoldierGame` encounter, setting `guardDefeated`; the **builder**, with `Game.TunnelTwigCost` twigs, walks to the east wall's sign and plays `BuilderGame`; ≥4 floors sets `tunnelBuilt` and removes the wall plug (`WorldLayout.BuildWalls`, `WorldDecor.PlugRoot`); the **worker** collects leaves/twigs everywhere plus honey (north zone, = 4 leaves) and crystals (east zone, = pieces) once those zones are open and revealed, and delivers to the nest (`Game.CompleteDelivery`). Switching role in the world costs `Game.RoleSwitchCost` coins (`RoleScreen.Open(..., current, cost)`). While a sub-game is open `WorldGame` hides its world/UI and sets `_busy`; sub-games restore the camera themselves. The roles you are not playing are covered by NPC squads (`WorldNpcs.cs`, a partial of `WorldGame`; see below); world state lives in `SaveData` so it can be synced by a future online mode.
- **`BuilderGame` / `SoldierGame`** – the two encounter mini-games, opened by `WorldGame` with `Open(parent, onClose, ...)` callbacks (`BuilderGame` reports the floors built; `SoldierGame` takes a first wave/wave count and reports victory). `BuilderGame` is a one-tap stacking tower: a block slides over the tower, tap to drop it, the overhang is cut off and falls, each floor is a piece and reaching the top gives a bonus; a total miss ends the run (`Game.CompleteBuild`). It moves the main camera up the tower and restores it in `OnDestroy`.
- **Minigame helpers** – `VirtualJoystick` (floating on-screen joystick attached to a transparent pad; `Value` is x/y in 0–1), `TapPad` (fires on pointer-down), `AntRunner` (moves the ant from analog joystick input via `SetInput`/`Move`, nest and building collision, `IsClear` for spawns), `ChaseCam` (follows the ant with a small zoom, restores the camera on exit), `TargetPointer` (edge-of-screen arrow to off-screen targets). The world obstacle constants live in `AntRunner` and mirror `NestView.NestEntrance`/`BuildingPos`; keep them in sync if the nest layout changes.
- **`SoldierGame` (dance battle)** – 5 waves, 3 lives: a beetle (`BeetleModel`) walks toward a squad of three soldier ants and a bubble asks for a shape; the player draws it with one finger on a `GesturePad` (touch capture + fading dotted trail), `GestureRecognizer` classifies it (line, zigzag, triangle, circle, star) from the simplified stroke's corners (no templates), and the squad plays the matching `AntDancer` move (`DanceMove`: hop, shimmy, spin, waltz, star) whatever shape was drawn; only the requested shape damages the enemy (star = 2). Coins are paid through `Game.CompleteBattle`. `AntDancer` drives an ant's `AntRig.Body`/legs procedurally (front legs act as arms) and restores the rest pose afterwards. To add a shape: extend `GestureShape`, its template in `GestureRecognizer.Template` (used for the icon), the recogniser rule, `AntDancer.MoveFor` and the move itself. `Antopia/Test Gestures` (`GestureTests.Run`, runnable with `-executeMethod Antopia.EditorTools.GestureTests.Run -batchmode -nographics -quit`) measures recognition accuracy on noisy synthetic strokes; re-run it after touching the recogniser.
- **Roles (`AntRoles`, `RoleScreen`)** – each ant colour is a role (`SaveData.role` indexes `AntRoles.All`): Obrera = red, Constructora = black, Soldado = brown, Exploradora = green. `RoleScreen` is a standalone screen (not the rebuilt-on-change overlay) that shows the four ants spinning on a stage at `Origin` (far from the nest) rendered by a second camera into a `RenderTexture`, with transparent buttons placed by projecting each ant to screen space; it does not save the role itself, the caller does.
- **World look (`WorldDecor`, `NestView`)** – `WorldDecor.Build` creates the 128 m ground plane with a runtime-generated tileable grass texture and merges all decoration (flowers, pebbles, tall grass, bushes ring) into one mesh per colour; the walkable zones stay clear, stone rows mark the walls and a far ring of bushes closes the edge. Buildings are composed from primitives and scale with level via `NestView.BuildingScale`, which `AntRunner.BuildingRadius` mirrors for collisions. `MinigameHud` is the shared minigame bar (stats, hint, exit button).
- **Sound, haptics and feel (`Sfx`, `Haptics`, `Juice`)** – there are no audio files: `Sfx` synthesises 20 effects and a looping background track in code on first use (`Sfx.Play(Sfx.Id.X)`, `Sfx.StartMusic()`), with a soft limiter; toggles for sound/music/vibration live in PlayerPrefs and in the gear overlay (`GameController.OpenSettings`). `Sfx.DebugReport` / `Antopia/Test Sonidos` (`SfxTests.Run`) checks the synthesis for NaNs and levels without listening. `Haptics` uses Android JNI for short vibrations (a dead `Handheld.Vibrate` reference makes Unity add the VIBRATE permission). `Juice` has `Popup` (floating text over a world point), `CamShake` (call `Trigger`, cameras add `Offset()`), `CountText` (HUD numbers that count up) and `ButtonFx` (press squash); `UiKit.MakeButton`/`IconButton` add the click sound and `ButtonFx` automatically, and `AntRig.Bounce` makes an ant hop in place.
- **NPC squads (`WorldNpcs.cs`)** – every role you are *not* playing has `Game.Helpers` (= 1 + Tuneles level / 4) visible NPC ants that do that role's job slowly and for real: worker NPCs collect from open zones and deliver via `Game.NpcDelivery` (no Despensa bonus, no quest/daily counters); explorer NPCs walk to the nearest fogged cell and call `RevealAt(pos, NpcReveal, true)`; builder NPCs stand at the tunnel sign, pay `TunnelTwigCost` once and accumulate `SaveData.npcWork[1]` until `Game.NpcBuildSeconds`; soldier NPCs dance in front of the guard accumulating `npcWork[0]` until `Game.NpcSoldierSeconds`. Movement reuses `AntRunner` (walls/blockers) with simple obstacle steering and `Route` through the wall gaps. Switching role swaps the squads (`SwapNpcs`); the shared outcomes are `ClearGuard`/`OpenTunnel`, also used by the player's own encounters. A label over the first working NPC shows the progress.
- **Guided quest (`Quests`)** – an ordered chain of `Quest` steps (progress read from `SaveData` counters and world flags, so it survives restarts) that walks through all four roles; `WorldGame` shows the current one in a banner, points the edge arrow at its waypoint when you already play the right role, and pays coins on completion (`Quests.CompleteFinished`). Add a step by adding an entry to `Quests.All` (and a counter to `SaveData` if needed).
- **`AntModel` / `AntRig`** – primitive-built "cute" 3D ant (big round head, shiny eyes, cheeks, smile, bulb antennae, stubby legs) with one colour and one head accessory per role (sprout, hard hat, helmet, explorer hat); `AntRig` animates the legs from the transform's speed (or `ForcedSpeed`). Ant materials are runtime clones of `Resources/Materials/Ant` via `AntModel.Tint(color, smoothness)`.

Economy loop: forage → leaves/twigs → sell leaves for coins; twigs fund the builder minigame → pieces; coins + pieces buy the three building upgrades (Despensa = harvest multiplier, Tuneles = passive ants, Camara real = leaf price), max level 10. A second upgrade track for the worker (`SaveData.forageLevels`: capacity, speed, pickup radius, luck = chance a pickup counts double; max level 5) costs coins + twigs and is exposed through the `Game.Forage*` members, which `WorldGame` reads while playing the worker. Both tracks are shown as tabs in the Nido overlay (`GameController.OpenNest`).

## Packages

`Packages/manifest.json` includes Unity IAP (`com.unity.purchasing`), Authentication, Cloud Code and Cloud Save, but no game code uses them yet (only `Resources/BillingMode.json` sets the store to GooglePlay). Persistence is currently local-only.
